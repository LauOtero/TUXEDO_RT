## 1. Objetivos y Alcance

### 1.1 Qué es KETP·URT

KETP·URT (Klipper Ethernet Transport Protocol · Ultra Real-Time) es el protocolo de comunicación entre un host Klipper y uno o varios MCUs de impresora 3D. Opera exclusivamente sobre Ethernet físico usando chips WIZnet W5500, W6100 o W6300 en modo MACRAW, con EtherType propio `0x88B7`.

El protocolo cubre cuatro responsabilidades en un único stack coherente:

- **Transporte fiable** de comandos de control y configuración del firmware del MCU.
- **Transporte de alta eficiencia** de comandos de movimiento de motores paso a paso, con compresión adaptativa Golomb-Rice.
- **Telemetría en tiempo real** de sensores de temperatura, corriente, acelerómetros y otros dispositivos.
- **Gestión del sistema**: sincronización de reloj hardware, ventanas RT deterministas, descubrimiento de nodos, actualización de firmware OTA y negociación de capacidades.

### 1.2 Objetivos de Rendimiento

| Métrica | **KETP·URT** |
|---|---|
| Ancho de banda físico | 12.5 MB/s (100BASE-T) |
| Latencia frame típica | < 0.2 ms |
| Jitter sin kernel RT | 2–5 ms |
| Jitter con PREEMPT-RT | < 0.1 ms |
| Buffer de anticipación de pasos sin RT | 10–15 ms |
| Buffer de anticipación de pasos con RT | 2–3 ms |
| Sesgo de sincronización de reloj | < 0.5 µs |
| Overhead de cabecera por frame | 15 bytes (fijo) |
| Overhead de cabecera por sub-frame | 3 bytes (fijo) |
| Overhead total para 1.5 KB de datos (4 sub-frames) | 41 bytes |

### 1.3 Fuera del Alcance

- Comunicación sobre UART, USB o CAN.
- Soporte de IPv4/IPv6 (el protocolo es Ethernet raw Layer 2).
- Cualquier mecanismo de encriptación o autenticación (se asume red física privada).

## 2. Arquitectura General

### 2.1 Topología Física

```
┌───────────────────────────────────────────────────────────────────────┐
│                       HOST (Raspberry Pi / PC)                        │
│                                                                       │
│  Klipper Python ──── ketp_urt_transport.py ──── AF_PACKET socket     │
│                                                    EtherType 0x88B7  │
└───────────────────────────────────┬───────────────────────────────────┘
                                    │  100BASE-T Ethernet
        ┌───────────────────────────┼──────────────────────────┐
        │                           │                          │
┌───────┴────────┐         ┌────────┴───────┐        ┌────────┴───────┐
│   MCU #0       │         │   MCU #1       │        │   MCU #2       │
│ STM32H7        │         │ RP2040         │        │ ESP32-S3       │
│ + W6300        │         │ + W5500        │        │ + W6100        │
│ NODE_ID=0      │         │ NODE_ID=1      │        │ NODE_ID=2      │
└────────────────┘         └────────────────┘        └────────────────┘
```

Un único host puede gestionar múltiples MCUs en el mismo segmento Ethernet. Cada MCU tiene una MAC única generada desde su chip ID y un `NODE_ID` asignado por el host durante el discovery. El campo `NODE_ID` en los sub-frames CMD permite multiplexar comandos para diferentes MCUs en un mismo frame Ethernet si fuera necesario, aunque en la práctica cada MCU tiene su propio socket de destino por MAC unicast.

### 2.2 Stack de Canales Lógicos

Un único frame Ethernet transporta sub-frames de cualquier canal. Los cuatro canales son independientes en cuanto a política ARQ, prioridad y semántica, pero comparten el mismo canal físico Ethernet y el mismo contador de secuencia del emisor.

```
┌─────────────────────────────────────────────────────────────────────────┐
│                         HOST (Klipper Python)                           │
│  ┌──────────────────────────────────────────────────────────────────┐   │
│  │                    ketp_urt_transport.py                         │   │
│  │  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌────────────────┐  │   │
│  │  │ Canal 0  │  │ Canal 1  │  │ Canal 2  │  │   Canal 3      │  │   │
│  │  │   CMD    │  │   MOVE   │  │   TELEM  │  │    CTRL        │  │   │
│  │  │ ARQ sel. │  │ ARQ acot.│  │ Best-efft│  │ ARQ completo   │  │   │
│  │  └────┬─────┘  └────┬─────┘  └────┬─────┘  └───────┬────────┘  │   │
│  │       └─────────────┴─────────────┴────────────────┘           │   │
│  │                     Frame Builder (15B hdr + sub-frames)        │   │
│  └─────────────────────────────┬───────────────────────────────────┘   │
│                     AF_PACKET EtherType 0x88B7                         │

└─────────────────────────────────────────────────────────────────────────┘
```

### 2.3 Relación Frame / Sub-Frames

```
Frame Ethernet (≤ 1500 bytes de payload L2)
└── Cabecera Ethernet (14 bytes)
└── KETP·URT Header (15 bytes, fijo)
    └── Payload KETP·URT (hasta 1400 bytes)
        ├── Sub-frame 0: [TYPE 1B][LEN 2B][BODY N bytes]
        ├── Sub-frame 1: [TYPE 1B][LEN 2B][BODY M bytes]
        ├── Sub-frame 2: [TYPE 1B][LEN 2B][BODY K bytes]
        └── ...  (hasta agotar PAYLOAD_LEN)

Ejemplo: un frame con CHRONO_SYNC + 2 batches de pasos + 1 comando
  14 (ETH) + 15 (KETP·URT hdr) + (3+12) + (3+42) + (3+38) + (3+9) = 142 bytes
```

## 3. Principios de Diseño

**P1 — Un solo frame, cuatro canales lógicos.** Los canales CMD, MOVE, TELEM y CTRL comparten el canal físico pero tienen políticas ARQ, prioridades y semánticas completamente independientes. Un frame puede contener sub-frames de más de un canal.

**P2 — Cabecera de frame fija de 15 bytes.** Toda la variabilidad (tipo de tráfico, compresión, modo de reloj) reside en los sub-frames. El parser del MCU lee siempre exactamente 15 bytes de cabecera de frame y 3 bytes de cabecera de sub-frame. Sin campos de longitud variable en las cabeceras.

**P3 — Compresión solo donde es óptima.** Golomb-Rice adaptativa se aplica únicamente al canal MOVE cuando el perfil de movimiento tiene alta varianza de deltas. Para movimiento uniforme se usa una representación de tres parámetros equivalente a `queue_step`. Para CMD y CTRL se usa codificación VLQ directa. Para TELEM se usan deltas de 4 bits para acelerómetros y valores raw de 16 bits para otros sensores.

**P4 — Timestamps de reloj capturados por hardware.** El timestamp T2 (recepción en el MCU) se captura en la función `recv_packet()` del driver WIZnet, antes de leer el payload, usando el DWT cycle counter de Cortex-M. T3 (transmisión desde el MCU) se captura justo antes del burst SPI. La latencia de software no contamina los cálculos de offset.

**P5 — ARQ diferenciado por semántica de canal.** CTRL necesita 10 reintentos porque discovery y OTA no tienen tiempo real; CMD necesita 5 porque los comandos de configuración son críticos; MOVE solo 2 porque un batch de pasos que llega fuera de ventana temporal es irrelevante y debe regenerarse; TELEM cero porque los datos de sensor tienen valor únicamente en el instante de captura.

**P6 — Control de flujo por carga del MCU, no por CWND.** El canal físico Ethernet dedicado no tiene contención real. El único cuello de botella es el MCU. El campo `MCU_LOAD` en `CHRONO_SYNC_RESP` es el mecanismo de backpressure correcto y suficiente.

**P7 — Descubrimiento dinámico y sesión negociada.** El host no necesita configuración estática de IPs ni MACs. Envía un broadcast y cada MCU responde con su identidad y capacidades. La sesión comienza con una negociación explícita de qué características están disponibles en ambos extremos.

**P8 — Los drivers de hardware no requieren modificación estructural.** La interfaz `struct ketp_driver` con sus funciones `init`, `send`, `send_sg`, `recv`, `poll` y `get_link_status` no cambia. Solo se añade una variable global de timestamp de recepción en cada driver.

```
Capa              Responsabilidad                         Implementación
────────────────  ──────────────────────────────────────  ──────────────────────────
Física            Señal eléctrica 100BASE-T               PHY integrado en WIZnet
Enlace            Frames MAC, EtherType 0x88B7             eth_link.c

```

El protocolo es stateful a nivel de sesión: el estado comienza en IDLE, pasa por DISCOVERED y NEGOTIATED hasta llegar a ACTIVE. Los frames solo se procesan plenamente en estado ACTIVE; en otros estados solo se aceptan los sub-frames de gestión necesarios para avanzar.

## 5. Especificación del Frame

### 5.1 Encapsulamiento Ethernet

```
Offset  Tamaño  Campo        Valor / Descripción
──────  ──────  ──────────── ──────────────────────────────────────────────────
  0       6     DST_MAC      MAC del destinatario (unicast o broadcast FF:FF:…)
  6       6     SRC_MAC      MAC del emisor
 12       2     ETHERTYPE    0x88B7
 14       N     FRAME_BODY   Cabecera KETP·URT + payload [+ CRC opcional]
```

Tamaño mínimo del frame Ethernet: 60 bytes (el hardware aplica padding automáticamente). El payload Ethernet L2 máximo es 1500 bytes. KETP·URT reserva un máximo de 1400 bytes para mantener margen operativo frente a encapsulados internos del driver y futuras extensiones de framing.

### 5.2 Cabecera KETP·URT — 15 bytes fijos

```
Offset  Tamaño  Campo        Tipo        Descripción
──────  ──────  ──────────── ─────────── ─────────────────────────────────────────
  0       1     MAGIC        uint8_t     Siempre 0xA7. Identifica el protocolo.
  1       1     VER_FLAGS    uint8_t     [7:4]=VERSION [3:2]=CHAN [1]=HAS_CRC [0]=FRAG
  2       4     SEQ          uint32_t BE Número de secuencia del emisor
  6       4     ACK          uint32_t BE Último SEQ del remoto procesado correctamente
 10       2     PAYLOAD_LEN  uint16_t BE Longitud del payload en bytes
 12       3     TIMESTAMP    uint8_t[3]  24 bits bajos del DWT_CYCCNT del emisor, BE
```

**Campo VER_FLAGS:**

```
Bit 7-4 │ VERSION = 0x1  — versión del protocolo
Bit 3-2 │ CHAN           — 0b00=CMD  0b01=MOVE  0b10=TELEM  0b11=CTRL
         │                 Canal primario del frame (el dominante en payload).
         │                 Un frame puede contener sub-frames de otros canales.
Bit 1   │ HAS_CRC        — 1 si los 4 últimos bytes del frame son CRC-32/MPEG-2.
         │                 Con Ethernet FCS activado en el chip WIZnet debe ser 0.
Bit 0   │ FRAG           — 1 si este frame es un fragmento de un payload mayor.
         │                 Si FRAG=1, los primeros 4 bytes del payload son
         │                 [FRAG_ID:2B BE][FRAG_OFFSET:2B BE].
```

Reglas de validación obligatorias del receptor:
- `VERSION` distinto de `0x1` implica descarte silencioso del frame.
- Si `HAS_CRC=1` y el CRC no valida, el frame se descarta sin ACK.
- Si `FRAG=1` y `KCAP_FRAG` no fue negociado en `AGREED_CAPS`, el frame se rechaza con `ERROR_REPORT(UNSUPPORTED)`.

**Campo TIMESTAMP:**

Los 3 bytes contienen los 24 bits menos significativos del DWT_CYCCNT del emisor en el instante de envío (TX) o recepción (RX). A 168 MHz cubre 99.8 ms antes de rollover, suficiente para todos los cálculos RTT del protocolo.

```c
/* Construcción del campo TIMESTAMP en el MCU */
uint32_t ts          = ketp_get_cycles(); /* DWT_CYCCNT */
hdr->timestamp[0]    = (ts >> 16) & 0xFF;
hdr->timestamp[1]    = (ts >>  8) & 0xFF;
hdr->timestamp[2]    =  ts        & 0xFF;
```

### 5.3 Cabecera de Sub-Frame — 3 bytes fijos

Cada sub-frame dentro del payload tiene una cabecera de 3 bytes seguida de su cuerpo:

```
Offset  Tamaño  Campo     Tipo        Descripción
──────  ──────  ───────── ─────────── ─────────────────────────────────────────
  0       1     SUB_TYPE  uint8_t     Tipo del sub-frame (ver §6)
  1       2     SUB_LEN   uint16_t BE Longitud del cuerpo en bytes
  3       N     SUB_BODY  uint8_t[]   Cuerpo del sub-frame
```

El receptor itera sub-frames consumiendo `3 + SUB_LEN` bytes por iteración hasta agotar `PAYLOAD_LEN`. `SUB_TYPE = 0xFF` es padding y se ignora.

### 5.4 Estructuras C

```c
/* ketp_urt.h */

#define KETP_URT_MAGIC         0xA7
#define KETP_URT_VERSION       0x01
#define KETP_URT_ETHERTYPE     0x88B7
#define KETP_URT_HEADER_SIZE   15
#define KETP_URT_SUBHDR_SIZE   3
#define KETP_URT_MAX_PAYLOAD   1400

#define KETP_URT_CHAN_CMD       0
#define KETP_URT_CHAN_MOVE      1
#define KETP_URT_CHAN_TELEM     2
#define KETP_URT_CHAN_CTRL      3

struct ketp_urt_header {
    uint8_t  magic;        /* 0xA7                                      */
    uint8_t  ver_flags;    /* VERSION[7:4] CHAN[3:2] HAS_CRC[1] FRAG[0] */
    uint32_t seq;          /* Big-endian                                 */
    uint32_t ack;          /* Big-endian                                 */
    uint16_t payload_len;  /* Big-endian                                 */
    uint8_t  timestamp[3]; /* 24-bit DWT_CYCCNT LSBs, Big-endian         */
} __attribute__((packed)); /* 15 bytes exactos                           */

struct ketp_urt_subhdr {
    uint8_t  sub_type;     /* Tipo del sub-frame                         */
    uint16_t sub_len;      /* Big-endian, longitud del cuerpo            */
} __attribute__((packed)); /* 3 bytes exactos                            */
```

## 7. Canal CMD — Comandos y Respuestas

### 7.1 CMD_VLQ (0x00) — Comando al MCU

Transporta un comando Klipper en su formato VLQ nativo, precedido por el `NODE_ID` del MCU destinatario:

```
CMD_VLQ body:
┌───────────┬──────────────────────────────────────────────────────────────┐
│ NODE_ID   │ VLQ_PAYLOAD                                                  │
│ [1B]      │ [N bytes — comando Klipper codificado en VLQ]                │
└───────────┴──────────────────────────────────────────────────────────────┘

NODE_ID: 0 para el MCU primario, 1-254 para MCUs secundarios.
VLQ_PAYLOAD: el comando exacto tal como lo generaría command_dispatch().
```

El MCU pasa `VLQ_PAYLOAD` directamente al dispatcher de comandos de Klipper sin transformación. Un único sub-frame CMD_VLQ puede contener exactamente un comando; si hay múltiples comandos, se incluyen múltiples sub-frames CMD_VLQ en el mismo frame.

### 7.2 CMD_RESPONSE (0x01) — Respuesta del MCU

Misma estructura que CMD_VLQ pero en dirección MCU→host. Se genera cuando el MCU tiene una respuesta a un comando previo.

### 7.3 CMD_ACK_ONLY (0x02) — ACK Puro

```
CMD_ACK_ONLY body (4 bytes):
┌────────────────────────────────────────────────────────────────────────┐
│ SEQ_ACK [uint32_t BE] — SEQ del frame que se está acusando             │
└────────────────────────────────────────────────────────────────────────┘
```

Se usa cuando el receptor quiere acusar recibo sin tener datos propios que enviar. En condiciones normales el ACK va piggybacked en el campo `ACK` de la cabecera del siguiente frame saliente; este sub-frame se usa solo cuando no hay tráfico pendiente en ningún canal.

### 7.4 CMD_NACK (0x03) — NACK Selectivo

```
CMD_NACK body (4 bytes):
┌────────────────────────────────────────────────────────────────────────┐
│ SEQ_LOST [uint32_t BE] — SEQ del frame que se solicita retransmitir   │
└────────────────────────────────────────────────────────────────────────┘
```

El emisor del NACK detectó un gap en la secuencia y solicita la retransmisión del frame específico. El receptor busca ese SEQ en su cola de retransmisión y lo reenvía inmediatamente, sin esperar el RTO.

## 8. Canal MOVE — Batches de Movimiento

### 8.1 Filosofía

El canal MOVE transmite eventos de paso de motores agrupados en batches. El host mantiene por cada OID (Object ID de stepper) un historial de varianza de deltas y selecciona automáticamente el tipo de batch:

- **STEP_BATCH_DELTA (0x10):** Para movimiento con input shaping, pressure advance o cualquier corrección que introduce variabilidad en los intervalos entre pasos. Usa compresión Golomb-Rice adaptativa.
- **STEP_BATCH_ABS (0x11):** Para movimiento con aceleración exactamente constante, donde la representación por tres parámetros es más compacta que la Golomb-Rice.

### 8.2 STEP_BATCH_DELTA (0x10)

```
STEP_BATCH_DELTA body:
┌──────┬──────────────────────────────────────────────────────────────────┐
│ B 0  │ OID [7:0] — Object ID del stepper motor (0–255)                 │
│ B 1  │ FLAGS: [7:4]=CLOCK_MODE  [3:0]=GOLOMB_K_INITIAL                 │
│ B 2  │ COUNT_H — número de pasos en el batch [15:8]                    │
│ B 3  │ COUNT_L — número de pasos en el batch [7:0]                     │
├──────┴──────────────────────────────────────────────────────────────────┤
│ CLOCK FIELD — tamaño y semántica según CLOCK_MODE:                      │
│                                                                          │
│   CLOCK_MODE=0000 → BASE_CLOCK_ABS [4B BE]                              │
│     Reloj MCU absoluto del primer paso en ticks.                         │
│     Obligatorio en el primer batch del OID en la sesión.                 │
│                                                                          │
│   CLOCK_MODE=0001 → BASE_CLOCK_DELTA_2 [2B BE, sin signo]               │
│     base_clock_nuevo = base_clock_anterior_este_OID + valor              │
│     Rango: 0–65535 ticks. Cubre 390 µs a 168 MHz.                       │
│                                                                          │
│   CLOCK_MODE=0010 → BASE_CLOCK_DELTA_3 [3B BE, sin signo]               │
│     base_clock_nuevo = base_clock_anterior_este_OID + valor              │
│     Rango: 0–16.777.215 ticks. Cubre 99.8 ms a 168 MHz.                 │
│                                                                          │
│   CLOCK_MODE=0011 → CLOCK_IMPLICIT (0 bytes)                            │
│     base_clock = tick_final_del_batch_anterior_de_este_OID.             │
│     El primer paso del nuevo batch ocurre justo tras el último del ant.  │
│                                                                          │
├──────────────────────────────────────────────────────────────────────────┤
│ DELTA_STREAM — stream de bits sin alineación de byte:                    │
│                                                                          │
│   COUNT deltas, cada uno codificado en Rice(k):                          │
│     delta[0] = tick_paso[0] − base_clock                                │
│     delta[i] = tick_paso[i] − tick_paso[i−1]   (i ≥ 1)                │
│     Todos los deltas son enteros positivos ≥ 1                           │
│                                                                          │
│   Marcador de actualización de k:                                        │
│     Si los próximos 8 bits del stream son todos 1 (valor 0xFF),         │
│     los siguientes 4 bits contienen el nuevo valor de k (1–15).         │
│     El emisor inserta este marcador cuando k cambia tras la revisión     │
│     de cada GOLOMB_UPDATE_INTERVAL pasos.                                │
│     El receptor actualiza k inmediatamente al encontrar el marcador.     │
│                                                                          │
│   El stream termina cuando se han decodificado COUNT deltas.             │
│   Los bits de padding del último byte se ignoran.                        │
└──────────────────────────────────────────────────────────────────────────┘
```

### 8.3 Codificación Golomb-Rice

Para un delta `d` y parámetro `k` (rango válido 1–15):

```
q = d >> k                       cociente entero
r = d & ((1 << k) − 1)           resto (k bits)
código = unario(q) ‖ binario(r, k)

unario(q)    → q bits '0' seguidos de un bit '1'
binario(r,k) → k bits de r, MSB primero

Ejemplos con k=4:
  d=5:   q=0 r=5   → "1"       + "0101"    = 5 bits  (vs 8 VLQ)
  d=22:  q=1 r=6   → "01"      + "0110"    = 6 bits  (vs 8 VLQ)
  d=100: q=6 r=4   → "0000001" + "0100"    = 11 bits (vs 16 VLQ)

Elección óptima de k: k ≈ floor(log2(delta_promedio))
  delta_promedio=200  → k=7   (log2(200)=7.64)
  delta_promedio=50   → k=5   (log2(50)=5.64)
  delta_promedio=5000 → k=12  (log2(5000)=12.3)

Actualización automática cada GOLOMB_UPDATE_INTERVAL=64 pasos:
  k_nuevo = clamp(floor(log2(suma_deltas / 64)), 1, 15)
```

### 8.4 STEP_BATCH_ABS (0x11)

Equivalente a un `queue_step` con tres parámetros. Óptimo para movimiento con aceleración cuadrática exactamente constante:

```
STEP_BATCH_ABS body:
┌──────┬──────────────────────────────────────────────────────────────────┐
│ B 0  │ OID [7:0]                                                        │
│ B 1  │ FLAGS: [7:4]=CLOCK_MODE  [3:0]=reservado=0                      │
│ B2-3 │ COUNT [uint16_t BE] — pasos representados                        │
├──────┴──────────────────────────────────────────────────────────────────┤
│ CLOCK FIELD — mismo esquema CLOCK_MODE que STEP_BATCH_DELTA             │
├──────────────────────────────────────────────────────────────────────────┤
│ INTERVAL [uint32_t BE] — intervalo inicial entre pasos en ticks MCU     │
│ ADD      [int32_t BE]  — incremento del intervalo por paso (con signo)  │
│                                                                          │
│   tick[0] = base_clock + INTERVAL                                        │
│   tick[i] = tick[i−1] + INTERVAL + ADD·i                               │
└──────────────────────────────────────────────────────────────────────────┘
```

### 8.5 MOVE_ACK (0x12) — Acuse de Recibo de Batch

El MCU envía `MOVE_ACK` tras procesar un batch. Permite al host verificar que los pasos están siendo aceptados dentro de la ventana temporal correcta:

```
MOVE_ACK body (8 bytes):
┌──────┬──────────────────────────────────────────────────────────────────┐
│ B 0  │ OID [7:0]                                                        │
│ B 1  │ STATUS: 0=OK  1=BUFFER_FULL  2=CLOCK_MISMATCH  3=OID_UNKNOWN   │
│ B2-3 │ COUNT_QUEUED [uint16_t BE] — pasos pendientes en buffer del MCU  │
│ B4-7 │ MCU_CLOCK_NOW [uint32_t BE] — reloj MCU al procesar el batch     │
└──────┴──────────────────────────────────────────────────────────────────┘
```

Si `STATUS != 0`, el host recalcula el batch con los parámetros ajustados y lo retransmite.

### 8.6 Selección Automática del Tipo de Batch

```python
# En ketp_urt_transport.py
def select_batch_type(deltas: list[int]) -> int:
    """Retorna 0x10 (DELTA) o 0x11 (ABS) según la variabilidad."""
    if len(deltas) < 4:
        return 0x11
    mean     = sum(deltas) / len(deltas)
    variance = sum((d - mean)**2 for d in deltas) / len(deltas)
    cv       = variance / (mean * mean) if mean > 0 else 0
    # CV > 0.05 indica variabilidad significativa (input shaping activo)
    return 0x10 if cv > 0.05 else 0x11
```

## 10. Canal CTRL — Control y Gestión

El canal CTRL transporta los sub-frames de gestión del protocolo. Tiene la mayor prioridad de transmisión y el ARQ más conservador. Un sub-frame CTRL puede incluirse en un frame de cualquier canal primario, lo que permite que una petición de sincronización no espere a que se vacíe la cola de movimiento.

### 10.1 KEEPALIVE (0x70)

Enviado por cualquier extremo cada 5 segundos cuando no hay otro tráfico. No requiere respuesta. Si el host no recibe ningún frame del MCU durante 15 segundos, vuelve al estado IDLE e inicia un nuevo discovery.

### 10.2 RESET_REQ (0x71)

```
RESET_REQ body (4 bytes):
┌────────────────────────────────────────────────────────────────────────┐
│ FLAGS [uint32_t BE]                                                    │
│   bit 0 = SOFT_RESET  — reinicio sin borrar configuración persistente  │
│   bit 1 = HARD_RESET  — equivalente a power-cycle                      │
│   bit 2 = ENTER_DFU   — entrar en modo DFU para actualización          │
└────────────────────────────────────────────────────────────────────────┘
```

## 11. CHRONO·SYNC — Sincronización de Reloj

### 11.1 Protocolo de Cuatro Timestamps

CHRONO·SYNC establece la correspondencia entre el reloj de pared del host (nanosegundos) y el reloj hardware del MCU (ticks DWT_CYCCNT). El mecanismo de cuatro timestamps elimina el sesgo por latencia de software:

```
Host                        Ethernet                       MCU
  │                                                          │
  │  T1 = time.time_ns()                                    │
  ├──────────── CHRONO_SYNC_REQ ───────────────────────────►│
  │                                                          │  ← driver recv_packet()
  │                                                          │    captura T2 = DWT_CYCCNT
  │                                                          │    ANTES de leer el payload
  │                                                          │
  │                                       T3 = DWT_CYCCNT capturado
  │                                            justo antes del burst SPI TX
  │◄──────────── CHRONO_SYNC_RESP ─────────────────────────┤
  │              {HOST_T1, MCU_T2, MCU_T3}                  │
  │                                                          │
  T4 = time.time_ns()
```

**Cálculo en el host:**

```
RTT_hardware = (T4 − T1) − (T3 − T2) × (1e9 / mcu_freq_hz)
               ↑ RTT total              ↑ Tiempo de procesado MCU excluido

offset_ns = (T1 + T4) / 2  −  T2 × (1e9 / mcu_freq_hz)
            ↑ Tiempo medio del host     ↑ T2 en nanosegundos del host

Actualización EWMA (α = 1/8):
  rtt_avg    ← α × RTT_hardware  + (1−α) × rtt_avg
  rtt_var    ← α × |RTT_hardware − rtt_avg| + (1−α) × rtt_var
  offset_avg ← α × offset_ns    + (1−α) × offset_avg

Conversión MCU ticks → nanosegundos host:
  host_ns(ticks) = ticks × (1e9 / mcu_freq_hz) + offset_avg
```

### 11.2 CHRONO_SYNC_REQ (0x30)

```
CHRONO_SYNC_REQ body (12 bytes):
┌──────┬──────────────────────────────────────────────────────────────────┐
│ B0-7 │ HOST_T1 [int64_t BE] — time.time_ns() del host al enviar        │
│ B8-9 │ SYNC_SEQ [uint16_t BE] — contador de petición de sync           │
│B10-11│ MCU_FREQ_HINT [uint16_t BE] — frecuencia esperada en unidades   │
│      │                            de 10 kHz (168 MHz = 16800)          │
└──────┴──────────────────────────────────────────────────────────────────┘
```

### 11.3 CHRONO_SYNC_RESP (0x31)

```
CHRONO_SYNC_RESP body (20 bytes):
┌──────┬──────────────────────────────────────────────────────────────────┐
│ B0-7 │ HOST_T1 [int64_t BE] — echo exacto del HOST_T1 recibido         │
│B8-11 │ MCU_T2 [uint32_t BE] — DWT_CYCCNT al detectar paquete disponible│
│B12-15│ MCU_T3 [uint32_t BE] — DWT_CYCCNT antes del burst SPI de TX     │
│B16-17│ SYNC_SEQ [uint16_t BE] — echo del SYNC_SEQ recibido             │
│B18-19│ MCU_LOAD [uint16_t BE] — carga del MCU en ‰ (0–1000)           │
└──────┴──────────────────────────────────────────────────────────────────┘
```

**Interpretación de MCU_LOAD:**

| Rango | Significado | Acción del host |
|---|---|---|
| 0–600 | Operación normal | Ninguna |
| 601–800 | Carga alta | Reducir intervalo CHRONO_SYNC a 50 ms |
| 801–950 | Carga crítica | Reducir batches al 50%; considerar RT_WINDOW |
| 951–1000 | Sobrecarga | Activar RT_WINDOW con STRICT_TIMING de inmediato |

### 11.5 Cadencia de Sincronización

Al establecer la sesión el host envía 10 peticiones en ráfaga con 5 ms de separación para converger el estimador rápidamente. Tras la convergencia, envía una petición cada 100 ms. La estimación de frecuencia del MCU se obtiene por regresión lineal sobre las últimas 30 muestras.

## 12. RT·WINDOW — Ventana RT Determinista

### 12.1 Concepto

La ventana RT declara explícitamente un intervalo temporal durante el cual el MCU se compromete a ejecutar un conjunto de comandos de movimiento con precisión de ±1 tick. Esto permite al host reducir el buffer de anticipación de pasos de 15 ms (sin kernel RT) hasta 2–3 ms (con PREEMPT-RT).

```
Eje de tiempo MCU (ticks):
────[T_now]────────────[T_open]──────────────────[T_close]──────────►
                         │                         │
                         ├──── RT·WINDOW id=N ─────┤
                         │                         │
           El host envía todos los batches          │
           de esta ventana con BUFFER_ADVANCE_MS    │
           de anticipación mínima.                  │
                                                    │
           El MCU garantiza error < ±1 tick         │
           para todos los pasos en [T_open, T_close]│
```

### 12.2 RT_WINDOW_OPEN (0x32)

```
RT_WINDOW_OPEN body (16 bytes):
┌──────┬──────────────────────────────────────────────────────────────────┐
│ B0-1 │ WINDOW_ID [uint16_t BE] — identificador incremental de ventana   │
│ B2-5 │ START_CLOCK [uint32_t BE] — reloj MCU de inicio en ticks         │
│ B6-9 │ DURATION_TICKS [uint32_t BE] — duración de la ventana en ticks   │
│B10-11│ N_COMMANDS [uint16_t BE] — batches esperados en esta ventana      │
│B12-13│ BUFFER_ADVANCE_MS [uint16_t BE] — anticipación mínima en ms      │
│B14-15│ FLAGS [uint16_t BE]                                               │
│      │   bit 0 = STRICT_TIMING    — error permitido: ±1 tick            │
│      │   bit 1 = DROP_ON_OVERRUN  — descartar si hay overflow de buffer  │
│      │   bit 2 = SYNC_BEFORE_OPEN — CHRONO_SYNC obligatorio antes de     │
│      │                               abrir la ventana                    │
└──────┴──────────────────────────────────────────────────────────────────┘
```

### 12.3 RT_WINDOW_CLOSE (0x33)

```
RT_WINDOW_CLOSE body (2 bytes):
┌────────────────────────────────────────────────────────────────────────┐
│ WINDOW_ID [uint16_t BE]                                                │
└────────────────────────────────────────────────────────────────────────┘
```

### 12.4 RT_WINDOW_ACK (0x34)

```
RT_WINDOW_ACK body (10 bytes):
┌──────┬──────────────────────────────────────────────────────────────────┐
│ B0-1 │ WINDOW_ID [uint16_t BE] — echo del WINDOW_ID                    │
│ B2-3 │ QUEUED [uint16_t BE] — batches aceptados en la ventana           │
│ B4-7 │ ACTUAL_CLOCK [uint32_t BE] — reloj MCU al recibir RT_WINDOW_OPEN │
│ B8-9 │ STATUS [uint16_t BE] — 0=OK  1=OVERFLOW  2=CLOCK_DRIFT  3=BUSY │
└──────┴──────────────────────────────────────────────────────────────────┘
```

```
Configuración del sistema          Buffer de anticipación  Respuesta a cambio
─────────────────────────────      ─────────────────────── ───────────────────
KETP·URT, Linux estándar           10–15 ms                15–30 ms
KETP·URT + PREEMPT-RT              3–5 ms                  5–10 ms
KETP·URT + RT·WINDOW               2–3 ms                  3–6 ms
KETP·URT + RT·WINDOW + Xenomai     ≤ 1 ms                  ≤ 2 ms
```

## 13. Sistema ARQ y Control de Flujo

### 13.1 Políticas ARQ por Canal

Cada canal tiene una política ARQ que refleja la semántica de sus datos:

```
Canal CTRL (3) — ARQ completo Karn/Jacobson
  RTO         = max(5 ms, RTT_avg + 4 × RTT_var)
  Reintentos  = 10
  Ventana     = 8 frames en vuelo
  Timeout     → ERROR_REPORT + transición a IDLE

Canal CMD (0) — ARQ selectivo
  RTO         = max(2 ms, RTT_avg + 2 × RTT_var)
  Reintentos  = 5
  Ventana     = 16 frames en vuelo
  NACK        → CMD_NACK con SEQ perdido; retransmisión inmediata

Canal MOVE (1) — ARQ acotado temporalmente
  RTO         = clamp(BUFFER_ADVANCE_MS / 3, 1 ms, 10 ms)
  Reintentos  = 2
  Ventana     = 4 frames en vuelo
  Frame fuera de ventana → MCU descarta, responde MOVE_ACK(CLOCK_MISMATCH)
                            El host regenera el batch con clock actualizado

Canal TELEM (2) — Best-effort, sin ARQ
  No se retransmite.
  Si el host detecta gap > TELEM_GAP_THRESHOLD frames consecutivos,
  envía TELEM_RESYNC (0x23) para reiniciar el clock base del sensor.
  TELEM_GAP_THRESHOLD predeterminado = 5
```

### 13.2 Control de Flujo por Carga del MCU

No existe un CWND. El canal Ethernet dedicado no tiene contención. El backpressure se implementa mediante el campo `MCU_LOAD` de `CHRONO_SYNC_RESP`:

```
MCU_LOAD ≤ 600‰    → Enviar a velocidad máxima
MCU_LOAD ∈ (600, 800‰] → Reducir tasa de batches al 75%
MCU_LOAD ∈ (800, 950‰] → Reducir tasa al 50%; activar RT_WINDOW si no activo
MCU_LOAD > 950‰    → RT_WINDOW STRICT_TIMING; pausar telemetría no crítica
```

Fast Retransmit se mantiene: 3 CMD_NACK idénticos consecutivos desencadenan retransmisión inmediata sin esperar el RTO.

### 13.3 Numeración de Secuencias

```
- Cada extremo mantiene un único contador SEQ global de 32 bits.
- El contador incrementa en 1 con cada frame enviado, sin importar el canal.
- El campo ACK en la cabecera es piggybacked y acusa todos los frames
  con SEQ ≤ ACK (cumulative ACK).
- Para ARQ selectivo (CMD) el receptor usa CMD_NACK con el SEQ exacto perdido.
- No hay head-of-line blocking: si MOVE pierde un frame, CMD y CTRL
  siguen procesándose con normalidad en los frames siguientes.
- Cada canal gestiona su propia cola de retransmisión.
- La comparación de SEQ/ACK usa aritmética serial módulo 2^32:
  `seq_after(a,b) = ((int32_t)(a - b) > 0)`. Con esto el wraparound es
  determinista y no requiere reinicializar sesión.
```

```
│ FW_VERSION [4B BE] — versión del firmware del MCU                      │
│ FW_HASH [10B]     — primeros 10 bytes del hash git del firmware        │
│ MCU_FREQ_KHZ [4B BE] — frecuencia del MCU en kHz (168000 = 168 MHz)    │
│ ETH_SPEED [1B]    — 1=10M  2=100M  3=1G                                │
│ NAME [32B]        — nombre del nodo (UTF-8, null-terminated)           │
└────────────────────────────────────────────────────────────────────────┘
```

### 14.3 DISC_ASSIGN (0x42) — Asignación de Node ID

El host asigna un `NODE_ID` al MCU y persiste la asociación MAC→ID:

```
DISC_ASSIGN body (40 bytes):
┌────────────────────────────────────────────────────────────────────────┐
│ CMD [1B]        — siempre 0xA2                                         │
│ TARGET_MAC [6B] — MAC del MCU objetivo                                 │
│ NODE_ID [1B]    — ID asignado (0–254; 255 = desasignar)                │
│ NAME [32B]      — nombre asignado (UTF-8, null-terminated)             │
└────────────────────────────────────────────────────────────────────────┘
```

El MCU persiste `NODE_ID` y `NAME` en flash usando `HAL_SaveConfig()`.

### 14.4 DISC_WIFI_CONFIG (0x43) — Configuración WiFi

Para MCUs con interfaz WiFi (ESP32). Permite configurar credenciales remotamente:

```
DISC_WIFI_CONFIG body (variable):
┌────────────────────────────────────────────────────────────────────────┐
│ CMD [1B]          — siempre 0xA5                                       │
│ TARGET_MAC [6B]   — MAC del MCU objetivo                               │
│ SSID [32B]        — SSID de la red WiFi (UTF-8, null-terminated)       │
│ PASSWORD [64B]    — Contraseña (UTF-8, null-terminated)                │
│ STATIC_IP [4B]    — IP estática (0.0.0.0 para DHCP)                   │
│ NETMASK [4B]      — Máscara de subred                                  │
│ GATEWAY [4B]      — Puerta de enlace                                   │
│ FLAGS [1B]        — bit 0 = habilitar WiFi                             │
└────────────────────────────────────────────────────────────────────────┘
```

Restricciones operativas obligatorias para `DISC_WIFI_CONFIG`:
- Solo se acepta en estado `DISCOVERED` o `NEGOTIATED`; en `ACTIVE` debe rechazarse con `ERROR_REPORT(STATE_MISMATCH)`.
- Requiere `PAIRING_WINDOW` activa iniciada por pulsador físico o pin de servicio en el MCU.
- El valor de `PASSWORD` no puede registrarse en logs y debe sobrescribirse en RAM tras persistir la configuración.

## 15. OTA — Actualización de Firmware

### 15.1 Flujo del Proceso OTA

```
Host                                                MCU
  │                                                  │
  ├──── OTA_START (size, SHA256, flags) ────────────►│
  │                                                  │  Borra flash, inicia sesión OTA
  │◄─── OTA_STATUS (IN_PROGRESS, 0 bytes) ──────────┤
  │                                                  │
  ├──── OTA_DATA (offset=0, datos[0..N]) ───────────►│
  ├──── OTA_DATA (offset=N+1, datos[N+1..]) ────────►│
  │           ... (múltiples bloques) ...             │
  ├──── OTA_DATA (offset=last) ─────────────────────►│
  │                                                  │
  ├──── OTA_END (final_offset=total_size) ──────────►│
  │                                                  │  Verifica SHA-256
  │                                                  │  Si OK: responde SUCCESS y reinicia
  │                                                  │  Si falla: responde ERROR_HASH
  │◄─── OTA_STATUS (SUCCESS o ERROR_HASH) ──────────┤
```

### 15.2 OTA_START (0x50)

```
OTA_START body (40 bytes):
┌────────────────────────────────────────────────────────────────────────┐
│ TOTAL_SIZE [4B BE]   — tamaño total del firmware en bytes              │
│ SHA256_HASH [32B]    — hash SHA-256 del firmware completo              │
│ FLAGS [4B BE]                                                           │
│   bit 0 = VERIFY_ON_END       — verificar hash antes de reiniciar     │
│   bit 1 = RESTART_ON_SUCCESS  — reiniciar automáticamente si OK        │
│   bit 2 = BACKUP_CURRENT      — conservar firmware actual si hay espac.│
└────────────────────────────────────────────────────────────────────────┘
```

La verificación SHA-256 es obligatoria. El MCU no reiniciará si el hash no coincide.

### 15.3 OTA_DATA (0x51)

```
OTA_DATA body:
┌────────────────────────────────────────────────────────────────────────┐
│ OFFSET [4B BE]   — offset de este bloque desde el inicio del firmware  │
│ DATA [N bytes]   — datos del bloque (N = SUB_LEN − 4, máx 1396 bytes) │
└────────────────────────────────────────────────────────────────────────┘
```

El MCU puede recibir bloques fuera de orden y mantiene un bitmap interno de bloques recibidos.

### 15.4 OTA_END (0x52)

```
OTA_END body (4 bytes):
┌────────────────────────────────────────────────────────────────────────┐
│ FINAL_OFFSET [4B BE] — debe igualar TOTAL_SIZE para ser válido         │
└────────────────────────────────────────────────────────────────────────┘
```

### 15.5 OTA_STATUS (0x53)

```
OTA_STATUS body (8 bytes):
┌──────┬──────────────────────────────────────────────────────────────────┐
│ B 0  │ STATUS: 0=IN_PROGRESS  1=SUCCESS  2=ERROR_HASH                  │
│      │         3=ERROR_FLASH  4=ERROR_SIZE  5=ABORTED                  │
│ B1-3 │ PADDING [3B] — reservado, debe ser 0                             │
│ B4-7 │ PROGRESS [uint32_t BE] — bytes escritos en flash hasta ahora    │
└──────┴──────────────────────────────────────────────────────────────────┘
```

- `ERROR_REPORT` se envía desde cualquier estado al detectar un sub-frame inválido.

### 17.2 Orden de Procesamiento en `ketp_urt_poll()`

```c
void ketp_urt_poll(void) {
    /* 1. Recepción y dispatch */
    int len = current_driver->recv(rx_buf, KETP_MBUF_SIZE);
    if (len > 0) {
        uint16_t offset; int is_urt;
        if (ketp_eth_parse_header(rx_buf, len, &offset, &is_urt) == 0
            && is_urt) {
            ketp_urt_rx_timestamp = ketp_get_cycles();   /* captura T2 */
            ketp_urt_dispatch(rx_buf + offset,
                              len - offset,
                              rx_buf + 6);               /* src_mac */
        }
    }

    /* 2. TX por orden de prioridad */
    ketp_urt_flush_ctrl();          /* CTRL: máxima prioridad          */
    ketp_urt_flush_move_acks();     /* MOVE_ACK: latencia de feedback   */
    ketp_urt_flush_telem();         /* TELEM: si sensores listos        */
    ketp_urt_flush_cmd_responses(); /* CMD_RESPONSE: menor prioridad    */

    /* 3. ARQ: revisar timeouts y retransmitir */
    ketp_urt_arq_tick();

    /* 4. Keepalive si no ha habido tráfico */
    ketp_urt_keepalive_check();
}
```

### 17.3 Dispatcher de Sub-Frames

```c
void ketp_urt_dispatch(const uint8_t *payload, uint16_t plen,
                        const uint8_t *src_mac) {
    if (plen < KETP_URT_HEADER_SIZE) return;
    const struct ketp_urt_header *hdr =
        (const struct ketp_urt_header *)payload;
    uint16_t payload_len = be16_to_cpu(hdr->payload_len);
    if (payload_len + KETP_URT_HEADER_SIZE > plen) return;

    process_ack(be32_to_cpu(hdr->ack));

    const uint8_t *ptr = payload + KETP_URT_HEADER_SIZE;
    const uint8_t *end = ptr + payload_len;

    while (ptr + KETP_URT_SUBHDR_SIZE <= end) {
        uint8_t  stype = ptr[0];
        uint16_t slen  = (ptr[1] << 8) | ptr[2];
        const uint8_t *body = ptr + KETP_URT_SUBHDR_SIZE;
        ptr += KETP_URT_SUBHDR_SIZE + slen;
        if (ptr > end) break;

        switch (stype) {
        case 0x00: klipper_command_dispatch(body + 1, slen - 1); break;
        case 0x02: process_ack(be32_load(body));                  break;
        case 0x03: process_nack(be32_load(body));                 break;
        case 0x10: step_batch_delta_process(body, slen);          break;
        case 0x11: step_batch_abs_process(body, slen);            break;
        case 0x30: chrono_sync_respond(body, slen,
                       ketp_urt_rx_timestamp, src_mac);           break;
        case 0x32: rt_window_open(body, slen);                    break;
        case 0x33: rt_window_close((body[0]<<8)|body[1]);         break;
        case 0x40: urt_discovery_respond(src_mac);                break;
        case 0x42: urt_discovery_assign(body, slen, src_mac);     break;
        case 0x43: urt_wifi_config(body, slen, src_mac);          break;
        case 0x50:
        case 0x51:
        case 0x52: urt_ota_process(body, slen, stype);            break;
        case 0x60: urt_caps_respond(body, slen, src_mac);         break;
        case 0x70: ketp_urt_keepalive_received();                 break;
        case 0x71: urt_handle_reset(be32_load(body));             break;
        case 0x23: telem_resync(body, slen);                      break;
        case 0xFF: break; /* padding */
        default:
            urt_send_error_report(be32_to_cpu(hdr->seq), stype, 3);
            break;
        }
    }
}
```

```c
int ketp_eth_parse_header(const uint8_t *buffer, uint16_t len,
                          uint16_t *payload_offset, int *is_urt) {
    if (!buffer || !payload_offset || !is_urt || len < 14) return -1;
    uint16_t etype = ((uint16_t)buffer[12] << 8) | buffer[13];

    *is_urt          = 1;
    *payload_offset  = 14;
    return 0;
```

### 18.3 `step_batch.c` — Decodificador Golomb-Rice

```c
#include "ketp_urt.h"
#include "step_batch.h"

typedef struct {
    uint32_t last_clock;
    uint8_t  golomb_k;
    uint32_t step_count;
    uint64_t delta_sum;
} oid_state_t;

static oid_state_t oid_state[KETP_URT_MAX_STEPPERS];

static uint32_t rice_decode(const uint8_t **data, int *bit_pos, uint8_t k) {
    uint32_t q = 0;
    while (!read_bit(data, bit_pos)) q++;
    uint32_t r = read_bits(data, bit_pos, k);
    return (q << k) | r;
}

void step_batch_delta_process(const uint8_t *body, uint16_t len) {
    if (len < 4) return;
    uint8_t  oid        = body[0];
    uint8_t  flags      = body[1];
    uint16_t count      = ((uint16_t)body[2] << 8) | body[3];
    uint8_t  clock_mode = (flags >> 4) & 0x0F;
    uint8_t  k_init     = flags & 0x0F;

    if (oid >= KETP_URT_MAX_STEPPERS) {
        urt_send_error_report(0, 0x10, 2 /* BAD_OID */); return;
    }

    const uint8_t *ptr = body + 4;
    uint32_t base_clock;
    switch (clock_mode) {
    case 0: base_clock  = be32_load(ptr); ptr += 4; break;
    case 1: base_clock  = oid_state[oid].last_clock + be16_load(ptr);
            ptr += 2; break;
    case 2: base_clock  = oid_state[oid].last_clock + be24_load(ptr);
            ptr += 3; break;
    default: base_clock = oid_state[oid].last_clock; break;
    }

    uint8_t k = (k_init > 0) ? k_init : oid_state[oid].golomb_k;
    if (k == 0 || k > 15) k = KETP_URT_GOLOMB_K_DEFAULT;

    int bit_pos = 0;
    uint32_t cur = base_clock;

    for (uint16_t i = 0; i < count; i++) {
        if (peek_bits(&ptr, &bit_pos, 8) == 0xFF) {
            skip_bits(&ptr, &bit_pos, 8);
            k = (uint8_t)read_bits(&ptr, &bit_pos, 4);
            if (k == 0 || k > 15) k = KETP_URT_GOLOMB_K_DEFAULT;
            oid_state[oid].golomb_k = k;
        }
        uint32_t delta = rice_decode(&ptr, &bit_pos, k);
        cur += delta;
        stepcompress_queue_step(oid, cur);   /* entrega al scheduler */

        oid_state[oid].delta_sum  += delta;
        oid_state[oid].step_count++;
        if (oid_state[oid].step_count >= KETP_URT_GOLOMB_UPDATE_INT) {
            uint32_t avg = (uint32_t)(oid_state[oid].delta_sum /
                                       KETP_URT_GOLOMB_UPDATE_INT);
            uint8_t nk = 1;
            while ((1u << nk) < avg && nk < 15) nk++;
            oid_state[oid].golomb_k   = nk;
            oid_state[oid].step_count = 0;
            oid_state[oid].delta_sum  = 0;
        }
    }
    oid_state[oid].last_clock = cur;
    urt_send_move_ack(oid, 0, stepcompress_queued(oid), ketp_get_cycles());
}
```

## 19. Implementación Host

### 19.1 `ketp_urt_transport.py` — Esqueleto Principal

```python
# klippy/extras/ketp_urt_transport.py

import socket, struct, threading, time, logging, math, statistics
from typing import Optional, Callable

ETHERTYPE  = 0x88B7
MAGIC      = 0xA7
VERSION    = 0x01
HDR_SIZE   = 15
SUBHDR     = 3
MAX_PAYLOAD = 1400

CHAN_CMD, CHAN_MOVE, CHAN_TELEM, CHAN_CTRL = 0, 1, 2, 3


class KetpUrtSession:
    """
    Gestiona la sesión completa KETP·URT con un MCU:
    discovery → caps → operación → OTA → desconexión.
    """

    def __init__(self, interface: str):
        self.iface      = interface
        self._sock      = None
        self._mcu_mac   = None
        self._host_mac  = None
        self._tx_seq    = 0
        self._acked_seq = 0
        self._mcu_freq  = 168_000_000   # Hz, actualizado por CAPS_RESP
        self._offset_ns = 0.0
        self._rtt_avg   = 500_000.0     # ns
        self._rtt_var   = 100_000.0     # ns
        self._caps      = 0
        self._lock      = threading.Lock()
        self._callbacks: dict[int, Callable] = {}
        self._sync_pending: dict[int, int] = {}
        self._sync_seq  = 0
        self._running   = False
        self._state     = 'IDLE'

    # ── Conexión ─────────────────────────────────────────────────────────

    def connect(self) -> bool:
        """Abre socket, realiza discovery y negocia capacidades."""
        import fcntl
        self._sock = socket.socket(socket.AF_PACKET, socket.SOCK_RAW,
                                   socket.htons(ETHERTYPE))
        self._sock.bind((self.iface, 0))
        self._sock.settimeout(0.1)
        ifreq = struct.pack('256s', self.iface[:15].encode())
        res   = fcntl.ioctl(self._sock.fileno(), 0x8927, ifreq)
        self._host_mac = res[18:24]

        self._send_subframe(CHAN_CTRL, 0x40, b'',
                            dst=b'\xff\xff\xff\xff\xff\xff')
        logging.info(f"KETP·URT: discovery en {self.iface}")

        deadline = time.monotonic() + 2.0
        while time.monotonic() < deadline:
            try:
                data = self._sock.recv(2048)
                if self._try_disc_resp(data):
                    self._negotiate_caps()
                    self._start_sync_burst()
                    self._state = 'ACTIVE'
                    return True
            except socket.timeout:
                pass
        return False

    def _negotiate_caps(self):
        host_caps = (KCAP_STEP_BATCH_DELTA | KCAP_STEP_BATCH_ABS |
                     KCAP_CHRONO_SYNC_HW   | KCAP_TELEM_SENSOR   |
                     KCAP_TELEM_ADXL345    | KCAP_RT_WINDOW       |
                     KCAP_MULTI_SUBFRAME   | KCAP_OTA_SHA256)
        self._send_subframe(CHAN_CTRL, 0x60, struct.pack('>I', host_caps))

    def _start_sync_burst(self):
        """10 peticiones de sync en ráfaga para convergencia rápida."""
        for _ in range(10):
            self._send_chrono_sync()
            time.sleep(0.005)

    # ── Construcción de frames ────────────────────────────────────────────

    def _build_frame(self, chan: int, subframes: list[bytes],
                     dst: Optional[bytes] = None) -> bytes:
        payload = b''.join(subframes)
        assert len(payload) <= MAX_PAYLOAD
        with self._lock:
            seq = self._tx_seq
            self._tx_seq = (self._tx_seq + 1) & 0xFFFFFFFF
        ts = int(time.perf_counter_ns() // 6) & 0xFFFFFF
        hdr = bytes([MAGIC, (VERSION << 4) | (chan << 2)]) + \
              struct.pack('>II', seq, self._acked_seq) + \
              struct.pack('>H', len(payload)) + \
              bytes([(ts >> 16) & 0xFF, (ts >> 8) & 0xFF, ts & 0xFF])
        mac = dst if dst else self._mcu_mac
        return mac + self._host_mac + struct.pack('>H', ETHERTYPE) + hdr + payload

    def _build_subframe(self, stype: int, body: bytes) -> bytes:
        return bytes([stype]) + struct.pack('>H', len(body)) + body

    def _send_subframe(self, chan: int, stype: int, body: bytes,
                       dst: Optional[bytes] = None):
        frame = self._build_frame(chan, [self._build_subframe(stype, body)], dst)
        self._sock.send(frame)

    # ── API pública ──────────────────────────────────────────────────────

    def send_cmd(self, vlq_payload: bytes, node_id: int = 0):
        """Envía un comando VLQ al MCU."""
        body = bytes([node_id]) + vlq_payload
        self._send_subframe(CHAN_CMD, 0x00, body)

    def send_step_batch_delta(self, oid: int, base_clock: int,
                               deltas: list[int], k: int = 8,
                               clock_mode: int = 0):
        """Envía un batch de pasos comprimido Golomb-Rice."""
        from ketp_urt_golomb import encode_delta_batch
        body = encode_delta_batch(oid, base_clock, deltas, k, clock_mode)
        self._send_subframe(CHAN_MOVE, 0x10, body)

    def send_step_batch_abs(self, oid: int, base_clock: int, count: int,
                             interval: int, add: int, clock_mode: int = 0):
        """Envía un batch de pasos por tres parámetros."""
        flags = (clock_mode & 0x0F) << 4
        body  = struct.pack('>BBHII', oid, flags, count, interval, add)
        # clock_mode=0 implica base_clock de 4 bytes al inicio
        if clock_mode == 0:
            body = bytes([oid, flags]) + struct.pack('>HI', count, base_clock) + \
                   struct.pack('>Ii', interval, add)
        self._send_subframe(CHAN_MOVE, 0x11, body)

    def _send_chrono_sync(self):
        t1_ns = time.time_ns()
        seq   = self._sync_seq
        self._sync_seq = (seq + 1) & 0xFFFF
        self._sync_pending[seq] = t1_ns
        body  = struct.pack('>qHH', t1_ns, seq, self._mcu_freq // 10000)
        sf    = self._build_subframe(0x30, body)
        # CHRONO_SYNC puede ir piggybacked en frame MOVE
        self._sock.send(self._build_frame(CHAN_CTRL, [sf]))

    def mcu_to_host_ns(self, ticks: int) -> int:
        """Convierte ticks MCU a nanosegundos del host."""
        return int(ticks * 1_000_000_000.0 / self._mcu_freq + self._offset_ns)

    # ── Recepción ────────────────────────────────────────────────────────

    def receive_loop(self):
        """Ejecutar en hilo dedicado."""
        self._running = True
        while self._running:
            try:
                data  = self._sock.recv(2048)
                rx_ns = time.time_ns()
                if len(data) < 14 + HDR_SIZE: continue
                if struct.unpack_from('>H', data, 12)[0] != ETHERTYPE: continue
                if data[14] != MAGIC: continue
                self._process_frame(data[14:], rx_ns)
            except socket.timeout:
                pass

    def _process_frame(self, frame: bytes, rx_ns: int):
        seq  = struct.unpack_from('>I', frame, 2)[0]
        plen = struct.unpack_from('>H', frame, 10)[0]
        if plen + HDR_SIZE > len(frame):
            return
        with self._lock:
            self._acked_seq = seq

        ptr = HDR_SIZE
        end = ptr + plen
        while ptr + SUBHDR <= end:
            stype = frame[ptr]
            slen  = struct.unpack_from('>H', frame, ptr + 1)[0]
            if ptr + SUBHDR + slen > end:
                break
            body  = frame[ptr + SUBHDR: ptr + SUBHDR + slen]
            ptr  += SUBHDR + slen
            self._dispatch_subframe(stype, body, rx_ns)

    def _dispatch_subframe(self, stype: int, body: bytes, rx_ns: int):
        if   stype == 0x01: self._on_cmd_response(body)
        elif stype == 0x12: self._on_move_ack(body)
        elif stype == 0x20: self._on_telem_sensor(body)
        elif stype == 0x21: self._on_telem_adxl345(body)
        elif stype == 0x22: self._on_telem_stats(body)
        elif stype == 0x31: self._on_chrono_resp(body, rx_ns)
        elif stype == 0x34: self._on_rt_window_ack(body)
        elif stype == 0x41: self._try_disc_resp_body(body)
        elif stype == 0x53: self._on_ota_status(body)
        elif stype == 0x61: self._on_caps_resp(body)
        elif stype == 0x72: self._on_error_report(body)

    def _on_chrono_resp(self, body: bytes, rx_ns: int):
        t1_ns, mcu_t2, mcu_t3, seq, mcu_load = struct.unpack_from('>qIIHH', body)
        if seq not in self._sync_pending: return
        del self._sync_pending[seq]

        mcu_proc = (mcu_t3 - mcu_t2) * (1_000_000_000.0 / self._mcu_freq)
        rtt_hw   = (rx_ns - t1_ns) - mcu_proc
        if rtt_hw <= 0: return

        A = 0.125
        self._rtt_avg   = A * rtt_hw  + (1-A) * self._rtt_avg
        self._rtt_var   = A * abs(rtt_hw - self._rtt_avg) + (1-A) * self._rtt_var
        t2_ns           = mcu_t2 * (1_000_000_000.0 / self._mcu_freq)
        offset          = (t1_ns + rx_ns) / 2.0 - t2_ns - mcu_proc / 2.0
        self._offset_ns = A * offset + (1-A) * self._offset_ns

        if mcu_load > 950:
            logging.warning(f"KETP·URT MCU sobrecargado: {mcu_load}‰")

    def _on_caps_resp(self, body: bytes):
        mcu_caps, freq_khz, sram_kb, flash_kb, agreed = \
            struct.unpack_from('>IIHHI', body[:16])
        self._caps     = agreed
        self._mcu_freq = freq_khz * 1000
        logging.info(f"KETP·URT caps acordadas: 0x{agreed:08X}, "
                     f"MCU freq={freq_khz}kHz")

    def stop(self):
        self._running = False
        if self._sock: self._sock.close()


# Bitmasks de capacidades (mirror de ketp_urt.h)
```

### 20.1 Overhead de Frame


### 20.3 Throughput de Movimiento

Para CoreXY 500 mm/s, 80 pasos/mm, 4 steppers, input shaping activo (×3 eventos):

```
Pasos/s: 4 × 500 × 80 × 3 = 480.000 eventos/s

Con STEP_BATCH_DELTA (k=6, delta medio ~400 ticks → ~5.8 bits/delta):
  Batch de 64 pasos: 4B hdr + 3B clock + ceil(64×5.8/8)=47B = 54 B
  480.000/64 = 7.500 batches/s × 54 = 405 KB/s
  Ethernet 100M = 12.500 KB/s → carga del canal: 3.2%

Con STEP_BATCH_ABS (movimiento uniforme, 3 parámetros):
  Batch 200 pasos: 4B hdr + 4B clock + 4B interval + 4B add = 16 B
  160.000/200 × 16 × 4 steppers = 51.2 KB/s → muy eficiente
```

### 20.4 Telemetría ADXL345

```
ADXL345 a 3200 Hz (input shaping de alta resolución):
  Sin comprimir:      3200 × 6 bytes = 19.200 bytes/s
  TELEM_ADXL345:      3200/32 batches × 81 bytes = 8.100 bytes/s
  Reducción: 58%

Latencia de procesado de input shaping:
  Batch de 32 muestras → 10 ms de latencia de acumulación
  vs. procesado muestra a muestra → 0.31 ms potencial
  Con pipeline de procesado solapado: ~5 ms latencia efectiva
```

## Apéndice A — Codificador y Decodificador Golomb-Rice

### A.1 Encoder Python

```python
# ketp_urt_golomb.py

import math
import struct

K_DEFAULT = 8
K_MIN     = 1
K_MAX     = 15
UPDATE_INT = 64


def _optimal_k(mean: float) -> int:
    if mean <= 0: return K_DEFAULT
    return max(K_MIN, min(K_MAX, int(math.log2(mean))))


def encode_delta_batch(oid: int, base_clock: int, deltas: list[int],
                        k_initial: int = K_DEFAULT,
                        clock_mode: int = 0,
                        last_clock: int = 0) -> bytes:
    """
    Codifica el cuerpo de un sub-frame STEP_BATCH_DELTA.
    clock_mode: 0=absoluto 4B, 1=delta 2B, 2=delta 3B, 3=implícito
    """
    assert all(d > 0 for d in deltas), "Todos los deltas deben ser > 0"
    assert 0 <= oid <= 255 and 1 <= k_initial <= 15

    flags  = ((clock_mode & 0x0F) << 4) | (k_initial & 0x0F)
    count  = len(deltas)
    header = bytes([oid, flags, (count >> 8) & 0xFF, count & 0xFF])

    if   clock_mode == 0: clock_f = base_clock.to_bytes(4, 'big')
    elif clock_mode == 1: clock_f = (base_clock - last_clock).to_bytes(2, 'big')
    elif clock_mode == 2: clock_f = (base_clock - last_clock).to_bytes(3, 'big')
    else:                 clock_f = b''

    bits  = []
    k     = k_initial
    s_sum = 0

    for i, d in enumerate(deltas):
        if i > 0 and i % UPDATE_INT == 0:
            nk = _optimal_k(s_sum / UPDATE_INT)
            s_sum = 0
            if nk != k:
                bits.extend([1] * 8)  # marcador de escape
                bits.extend([(nk >> (3 - j)) & 1 for j in range(4)])
                k = nk
        s_sum += d

        q = d >> k
        r = d & ((1 << k) - 1)
        bits.extend([0] * q + [1])
        bits.extend([(r >> (k - 1 - j)) & 1 for j in range(k)])

    stream = bytearray()
    for i in range(0, len(bits), 8):
        byte = 0
        for j in range(min(8, len(bits) - i)):
            byte |= bits[i + j] << (7 - j)
        stream.append(byte)

    return header + clock_f + bytes(stream)


def decode_delta_batch(body: bytes) -> dict:
    """Decodifica el cuerpo de un sub-frame STEP_BATCH_DELTA."""
    oid        = body[0]
    flags      = body[1]
    count      = (body[2] << 8) | body[3]
    clock_mode = (flags >> 4) & 0x0F
    k          = (flags & 0x0F) or K_DEFAULT

    ptr = 4
    if   clock_mode == 0: base = int.from_bytes(body[ptr:ptr+4],'big'); ptr+=4
    elif clock_mode == 1: base = int.from_bytes(body[ptr:ptr+2],'big'); ptr+=2
    elif clock_mode == 2: base = int.from_bytes(body[ptr:ptr+3],'big'); ptr+=3
    else:                 base = 0

    bits = []
    for b in body[ptr:]:
        bits.extend([(b >> (7 - i)) & 1 for i in range(8)])

    deltas = []
    pos    = 0
    for _ in range(count):
        if pos + 12 <= len(bits) and all(b == 1 for b in bits[pos:pos+8]):
            pos += 8
            k    = int(''.join(map(str, bits[pos:pos+4])), 2)
            pos += 4
            k    = max(K_MIN, min(K_MAX, k))

        q = 0
        while pos < len(bits) and bits[pos] == 0:
            q += 1; pos += 1
        pos += 1  # saltar '1'

        r    = int(''.join(map(str, bits[pos:pos+k])), 2)
        pos += k
        deltas.append((q << k) | r)

    return {'oid': oid, 'base_clock': base,
            'clock_mode': clock_mode, 'deltas': deltas}


def encode_abs_batch(oid: int, base_clock: int, count: int,
                      interval: int, add: int,
                      clock_mode: int = 0,
                      last_clock: int = 0) -> bytes:
    """Codifica el cuerpo de un sub-frame STEP_BATCH_ABS."""
    flags = (clock_mode & 0x0F) << 4
    if   clock_mode == 0: clock_f = base_clock.to_bytes(4, 'big')
    elif clock_mode == 1: clock_f = (base_clock - last_clock).to_bytes(2, 'big')
    elif clock_mode == 2: clock_f = (base_clock - last_clock).to_bytes(3, 'big')
    else:                 clock_f = b''
    return (bytes([oid, flags]) +
            struct.pack('>H', count) +
            clock_f +
            struct.pack('>Ii', interval, add))
```
